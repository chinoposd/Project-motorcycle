## Release sequence

1. Review the seven applied migrations and any later migration history before moving this branch to another Supabase project. In a linked project, run `npx supabase db push --dry-run --skip-vault` and inspect the listed versions before using `db push`. Never run `db reset --linked` on the shared project.
2. Configure the web build with `VITE_SUPABASE_URL` and **publishable** `VITE_SUPABASE_PUBLISHABLE_KEY`. Keep service keys, HMAC keys and offline signing keys out of `VITE_` variables and the browser. Publish the reviewed web bundle only after testing real Admin, Manager and Student/Employee accounts.
3. Have the project owner verify the central phone, Return Zone/Main Geofence coordinates, Privacy Notice/ride terms text and version, permitted days/hours, and the project's data-rights identity/legal procedure. Admin enters these with reasons. Leave Pilot thresholds and warning bands null until the Pilot yields approved values. Existing cooldowns are not recalculated when settings change.
4. Before deploying `vehicle-gateway`, agree and validate the ESP32/Raspberry Pi protocol: authoritative stopped/throttle/BMS/AI/GPS evidence, proximity, correlated command IDs and Motor Ready transitions, event IDs and monotonically ordered offline events. Use physical Real Riding Tests in the permitted closed area. `HARDWARE_PROTOCOL_APPROVED` and `HARDWARE_OFFLINE_PROTOCOL_APPROVED` must remain unset or `false` until the corresponding protocol is verified.
5. Provision a unique `VEHICLE_GATEWAY_SECRET` of at least 32 characters in Edge Function secrets and only on the authenticated gateway. Requests sign `timestamp + "\n" + UPPERCASE_METHOD + "\n" + URL_PATH + "\n" + exact_body` with HMAC-SHA256, send a 13-digit millisecond `x-vehicle-timestamp` and lowercase hex `x-vehicle-signature`. The five-minute timestamp check is transport replay protection, separate from Pilot safety timing. Device events also need unique event IDs and command/sequence correlation.
6. For offline NFC, provision a server-only Ed25519 private JWK and `OFFLINE_MANIFEST_KEY_ID`, distribute the matching public key to the ESP32, and set `OFFLINE_MANIFEST_LIFETIME_SECONDS` to a validated value no greater than 86400. The device must verify the signature, expiry, card/user binding, ordered event sequence and local safety/inspection evidence. A pending offline lease blocks online starts until invalidation and ordered reconciliation complete.
7. Deploy the reviewed `vehicle-gateway` and `privacy-worker` Edge Functions separately after their secrets and operational approvals exist. `supabase/config.toml` specifies `verify_jwt=false` because each function authenticates its own machine caller. The worker requires a unique 32+ character `PRIVACY_WORKER_SECRET` sent as a Bearer token. Configure a trusted scheduler for `operations_maintenance` and the worker; migrations alone do not schedule it. Function logs and recorded failed jobs need an operator response path.
8. Before running privacy deletion or project-end cleanup, obtain policy/advisor/legal review, validate identity and legal holds, inspect each job against real Storage/Auth records, and confirm the 30-day project-end obligation. The worker removes profile-photo objects through Storage API, minimizes SQL data, deletes the Auth account, and marks completion only after actual checks. An Admin click that merely closes a ticket is blocked by the new RPC. Do not run destructive cleanup for a test account in the shared project.

Once the privacy worker claims a deletion job, the cleanup phase is irreversible and a new hold is rejected. Review and record any legal/retention hold **before** the worker begins; pause the worker if new evidence may arrive. Access packages include account-scoped operational records. Shared raw offline manifests and Admin audit records involving other people require a separate reviewed policy process; they are identified as exclusions in the package.

## Role and behavior checkpoints

- Admin accounts do not drive. Driving Permission and induction confirmation are separate from account approval, including for Manager. Accepted appeals return only to Pending.
- Student and Employee use identical start policy. Manager is exempt from the start window and documented AI/Main Geofence checks, but not Driving Permission, stopped/throttle/BMS or physical safety checks. Rejected/Suspended accounts may appeal; Pending accounts may see availability without another rider's GPS.
- A web request creates a five-minute reservation, never an Active Session by itself. Only a trusted, correlated actual Motor Ready event changes the state. PendingEnd remains pending until stopped/motor-off/Return Zone or a documented physical exception. Policy changes, account suspension, logout and lost telemetry never cut power to a moving motorcycle.
- Admin and Manager share operational alert episodes and acknowledgment records. Acknowledgment does not clear a Safety Block. Manager may record a checked Safety Block clearance but cannot perform final service reopening, close an exceptional Session or resolve a vehicle conflict.
- Daily reports display missing duration/distance explicitly. User My Trips are owner-only and newest first; Admin corrections are audited. Phone GPS for Return Zone is a separate per-check record with raw coordinates deleted 30 days after each check, not an alternative start-location claim.
